# План реализации Transcribe Bot

Исходный план: 2026-11-09. Актуализирован: 2026-11-26.

Основной конвейер первой версии реализован. Состояние этапов ниже сверено
статически с исходным кодом коммита `7989da3`; готовность реальных интеграций
остаётся неподтверждённой. Документ фиксирует выполнение исходного плана и
оставшиеся шаги. Изменения кода, запуск проверок и реальные API-операции требуют
соответствующей авторизации; наличие пункта в плане её не предоставляет.

## Объём первой версии

Бот предназначен для небольшой группы пользователей: голосовые сообщения,
аудио и видео из Telegram преобразуются в текст с говорящими и таймкодами,
а также SRT при наличии корректных временных данных. Из видео предварительно
извлекается аудио. Сохраняются плоская структура модулей, Python 3.13 и workflow uv.

Принятые при реализации значения лимитов и тайм-аутов перечислены в
[SETUP.md](SETUP.md#константы-приложения). Их следует считать текущими настройками
кода, а не отдельными новыми требованиями пользователя. Форматы результата
и синтетическая демонстрация находятся в [README](../README.md#демонстрация-результата).

## Подтверждённые проверки и ограничения подтверждения

57 изолированных тестов, включая локальные проверки синтетического медиа,
`ruff check --no-cache .` и проверка совместимости установленных зависимостей.
Это результат конкретного локального запуска, а не настроенный CI или

Устройство тестов, команды и границы изоляции — в [TESTING.md](TESTING.md).
Распознавание реальных записей, точность определения языка, разделения говорящих,

Наличие реализации и успешные изолированные проверки не закрывают эти пункты.

## Оставшиеся шаги

### 1. Завершить предварительную валидацию настроек

Исходный план предусматривал проверку обязательных ключей и allowlist до polling.
Сейчас `config.py` читает значения, преобразует ID через `int` и не выполняет
общую валидацию; синтаксис токена проверяет aiogram при создании `Bot`.
Пустой allowlist запрещает доступ всем, диапазон ID не проверяется.

Для отдельной задачи разработки:

- Определить правила проверки пустых ключей, нечисловых и недопустимых ID,
  сохранив приоритет окружения над `.env` и закрытый доступ при пустом allowlist.
- Выдавать понятные ошибки до запуска polling без вывода значений секретов.
- Проверить закрытие уже созданных ресурсов при ошибках инициализации.
- Добавить изолированные проверки выбранных правил без реальных API-запросов.

Критерий завершения: правила документированы, неверные настройки обрабатываются
до polling, изолированные проверки подтверждают безопасную диагностику и очистку.

### 2. Подтвердить реальные интеграции и работу на целевых ОС

Отдельно согласовать сквозную проверку на выбранной записи, аккаунтах и операции.
Передача аудио AssemblyAI и возможная стоимость требуют явного разрешения.
Локальный тайм-аут не отменяет удалённое задание; повторная отправка записи может
создать новую платную операцию.

Проверить получение голоса, аудио и видео, доставку текста/TXT и SRT, сопоставление
субтитров с исходной временной шкалой и поведение при ошибках. Проверки на Windows
и macOS учитывать отдельно. Оценку распознавания связывать с конкретной записью,
не превращая её в гарантию точности для любых входов.

Критерий завершения: зафиксированы дата, окружение, сценарии, результаты и
оставшиеся ограничения без публикации ключей, пользовательских записей и
транскриптов. До этого соответствующее ограничение в README сохраняется.

## Границы дальнейшего развития

В исходный объём первой версии не входят группы, кружки (`video_note`), внешние
URL, публичная регистрация и оплата внутри бота. Постоянная история, восстановление
очереди и инфраструктура для файлов больше текущего лимита также не реализованы.
Извлечение аудио после скачивания не обходит ограничение размера исходного видео;
для больших файлов потребуется отдельное инфраструктурное решение.

Автоматическое удаление данных у AssemblyAI, отзыв удалённого задания и
идемпотентная доставка Telegram не реализованы. Это ограничения текущей версии,
а не обещанные функции следующего релиза. История/восстановление, большие файлы,
удаление у провайдера, новые форматы доступа и CI требуют отдельного определения
объёма работ; этот документ не назначает их к реализации.
