# Repository Guidelines

## Границы работы и безопасность

Соблюдайте применимые глобальные инструкции, режим задачи и разрешённую область
изменений. Чтение кода и предложенный план не разрешают реализацию. Сохраняйте
локальные, staged и untracked изменения пользователя, текущую ветку и upstream.
Не выполняйте staging, commit или push без соответствующего явного разрешения.
Не запускайте независимого reviewer автоматически.

Не обращайтесь к реальным Telegram/AssemblyAI API и не отправляйте записи на
платную транскрибацию без отдельного разрешения на конкретную операцию. Заглушки
и синтетические данные предпочтительны для проверок. Не выводите секреты,
пользовательские записи и транскрипты.

## Структура проекта

Проект — первая версия Telegram-бота на Python 3.13 с AssemblyAI. Сохраняйте
плоскую структуру модулей в корне; не вводите `src/` без отдельного согласования.

| Файл или каталог | Ответственность |
| --- | --- |
| `main.py` | Создание бота, клиентов и JobManager, подключение Router, запуск workers и polling, остановка ресурсов. |
| `config.py` | Загрузка `.env`, чтение трёх переменных окружения, константы лимитов и путей. |
| `handlers.py` | `/start`, `/help`, доступ, первичная проверка вложений, резервирование и постановка задания. |
| `processing.py` | Ограниченная очередь, workers, скачивание, временные файлы, статусы и доставка. |
| `media.py` | ffprobe, проверка медиа, извлечение первой аудиодорожки FFmpeg, управление subprocess. |
| `transcribe.py` | Асинхронный адаптер AssemblyAI, модели результата и нормализация; при импорте запросов нет, самостоятельной CLI-команды нет. |
| `formatters.py` | Текст/TXT и SRT из временных меток слов или реплик. |
| `errors.py` | Ожидаемые ошибки приложения с безопасным сообщением. |
| `logger_config.py` | `setup_logging()`: INFO+ в stderr, ERROR+ в `error.log` рядом с модулем. |
| `tests/` | Изолированные проверки на стандартном `unittest`, заглушки и синтетическое медиа. |
| `pyproject.toml`, `uv.lock`, `.python-version` | Зависимости, lockfile и выбор Python. |
| `README.md`, `docs/` | Обзор проекта и техническая документация. |

Описание модулей и жизненного цикла: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
[docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md) содержит состояние
этапов первой версии и оставшиеся шаги. Поддерживайте его при изменении реализации;
пункты плана сами по себе не разрешают разработку или реальные API-проверки.
Не перемещайте и не удаляйте документы без согласования.
Статусного документа `PROJECT_STATUS.md` нет; не вводите его без разрешения.

## Команды разработки

Используйте существующий workflow `uv` из корня проекта. Установку зависимостей
выполняйте только в рамках разрешённой настройки среды или разработки:

```sh
uv sync --locked
```

Запуск приложения обращается к Telegram, а обработка задания — к AssemblyAI:

```sh
uv run --locked python main.py
```

Для запуска нужны FFmpeg/ffprobe и соответствующие ключи. Не используйте
`uv run --locked python transcribe.py` как пример транскрибации: модуль только
объявляет модели, функции и сервис. Отдельной сборки и задач mise нет. При
разрешённом изменении зависимостей используйте uv и сохраняйте согласованность
`pyproject.toml` с `uv.lock`; не меняйте toolchain ради оформления документации.

## Стиль кода

Используйте четыре пробела, `snake_case` для модулей и функций, `PascalCase` для
классов и `UPPER_SNAKE_CASE` для констант. Добавляйте аннотации типов новым функциям.
Сохраняйте асинхронный подход aiogram и AssemblyAI SDK; блокирующие операции не
должны задерживать цикл событий. Запускайте subprocess без shell и освобождайте
ресурсы при ошибке, тайм-ауте и отмене.

`setup_logging()` вызывается в начале `main()`. В остальных модулях используйте
`from loguru import logger`, не добавляя параллельную систему логирования.
Диагностический вывод значений переменных в Loguru отключён.

Ruff указан в dev-зависимостях. В репозитории нет `[tool.ruff]`, `ruff.toml`,
`.ruff.toml` и CI workflow. Различайте установленный инструмент, проектные
настройки и фактически выполненную проверку; не объявляйте lint успешным по
одному наличию зависимости. Подробности — в [docs/TESTING.md](docs/TESTING.md).

## Тестирование и документация

Тесты размещайте в `tests/test_<module>.py`, методы называйте `test_*`.
Используются `unittest.TestCase` и `unittest.IsolatedAsyncioTestCase`; порог
покрытия не задан. Telegram и AssemblyAI подменяйте заглушками, файлы создавайте
во временных каталогах. Импорт `transcribe.py` безопасен относительно сетевых
запросов; `config.py` при импорте загружает `.env`, поэтому сохраняйте тестовую
изоляцию до импорта модулей приложения.

В рамках разрешённого запуска проверок в подготовленном окружении:

```sh
uv run --locked --no-sync python -B -m unittest discover -s tests -t . -v
uv run --locked --no-sync ruff check --no-cache .
```

`tests/__init__.py` подставляет фиктивные настройки, отключает загрузку `.env`
и блокирует внешние socket-соединения. Проверки FFmpeg/ffprobe используют
синтетическое медиа и пропускаются без инструментов. Не считайте их проверкой
реальных интеграций или качества распознавания.

При изменениях только документации выполняйте статическую проверку Markdown,
внутренних ссылок, примеров и diff; не запускайте функциональные тесты ради таких
правок. Поддерживайте русский язык, компактный ROOT README и один основной
источник подробностей по теме в `docs/`. Не создавайте пустые документы и не
выдавайте синтетические примеры за реальные результаты.

## Коммиты и pull request

В истории используются сообщения с префиксами `chore:` и `feat:`. Для документации
подходит краткое сообщение вида `docs: update project documentation`. В PR опишите
результат, фактически выполненные проверки, изменения конфигурации, если они
входят в задачу, и ссылку на задачу при наличии. Коммит и push — только по явному
разрешению; не включайте несвязанные изменения пользователя.

## Конфигурация и секреты

Перед запуском задайте `BOT_TOKEN`, `ASSEMBLYAI_API_KEY` и `ALLOWED_USER_IDS` в
`.env` рядом с `config.py` или в окружении. При импорте `config.py` файл загружается
через python-dotenv; только эти три настройки читаются через `os.getenv`, уже
заданное окружение имеет приоритет, включая пустые значения. Пустой allowlist
запрещает доступ всем; ID преобразуются в множество через `int` без проверки
диапазона. Нечисловой ID вызывает ошибку при импорте.

Остальные настройки заданы константами в `config.py` и из окружения не читаются.
Класса `Settings` и общей валидации конфигурации в этом модуле нет. Настройки и их
значения перечислены в [docs/SETUP.md](docs/SETUP.md).

Не публикуйте ключи, `.env`, `.venv`, логи, записи и транскрипты. `.gitignore`
исключает локальные настройки, окружения, кэши, данные и аудио/видеофайлы;
`.env.example` остаётся доступным для версионирования. Проверяйте каждый
добавляемый файл и diff, не полагайтесь только на `.gitignore`.
