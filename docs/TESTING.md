# Тестирование и статические проверки

## Организация и изоляция

Проверки в [tests/](../tests/) используют стандартный `unittest`, включая
`IsolatedAsyncioTestCase`, `AsyncMock` и `patch`. Дополнительный тестовый фреймворк
и обязательный порог покрытия не заданы.

[tests/__init__.py](../tests/__init__.py) до импорта приложения подставляет
фиктивные ключи и allowlist, задаёт `PYTHON_DOTENV_DISABLED=1`, отключает Loguru
и блокирует внешние socket-соединения. Локальные соединения loopback оставлены
для работы asyncio на Windows. Это защита Python-тестов, а не сетевая изоляция
всех дочерних процессов.

Telegram и операции транскрибации AssemblyAI подменяются заглушками. Отдельная
проверка создаёт и закрывает настоящий SDK-клиент с тестовым ключом без запросов.
Конфигурация проверяется на копии `config.py` с искусственным `.env` во временном
каталоге; реальные секреты и пользовательские записи не нужны.

| Область | Что проверяется |
| --- | --- |
| Конфигурация | Загрузка `.env`, приоритет окружения, пустой allowlist, константы. |
| Обработчики и очередь | Типы вложений, доступ, метаданные, переполнение, резервирования и одно задание на пользователя. |
| Обработка | Ограничение скачивания, worker pool, ошибки, тайм-ауты, отмена, очистка и завершение заданий. |
| AssemblyAI-адаптер | Параметры запроса, нормализация, ошибки, отмена загрузки, отсутствие повторной отправки и сетевых действий при импорте. |
| Форматирование и доставка | HTML как обычный текст, TXT в UTF-8, говорящие, SRT, отсутствующие/перекрывающиеся метки и ограниченные повторы доставки. |
| Жизненный цикл | Отсутствие инструментов до polling, закрытие ресурсов при ошибке polling. |
| Локальные медиа | Синтетические аудио и видео, первая дорожка, смещение аудио, отсутствие звука, повреждённые входы и плейлист. |

## Запуск тестов

Подготовьте окружение по [SETUP.md](SETUP.md), затем из корня проекта:

```sh
uv run --locked --no-sync python -B -m unittest discover -s tests -t . -v
```

`--no-sync` использует уже подготовленное окружение, `-B` отключает запись
байткода. Эти флаги не делают произвольный тест безопасным: при изменении тестов
проверяйте заглушки, окружение и побочные эффекты до запуска.

Вызов существующего интерпретатора без uv на macOS:

```sh
.venv/bin/python -B -m unittest discover -s tests -t . -v
```

В PowerShell на Windows:

```powershell
.venv\Scripts\python.exe -B -m unittest discover -s tests -t . -v
```

Локальные медиа-тесты работают во временных каталогах и требуют FFmpeg/ffprobe
в `PATH`. Без инструментов класс `LocalMediaIntegrationTests` пропускается;
успешный запуск с пропусками не подтверждает проверку извлечения аудио.

## Ruff

Ruff присутствует в группе `dev` в [pyproject.toml](../pyproject.toml) и зафиксирован
в [uv.lock](../uv.lock). В репозитории нет `[tool.ruff]`, `ruff.toml`, `.ruff.toml`
или CI workflow. Команда для ручной проверки без исправлений:

```sh
uv run --locked --no-sync ruff check --no-cache .
```

Проект не задаёт собственный набор правил; при отсутствии внешней конфигурации
применяются [настройки Ruff по умолчанию](https://docs.astral.sh/ruff/configuration/).
Наличие dev-зависимости не означает, что lint был выполнен или успешно завершён.
Ruff проверяет Python-код, а не Markdown; результаты форматирования и lint нельзя
считать эквивалентными. Здесь не задаётся новая политика форматирования.

## Границы подтверждения

Изолированные проверки не подтверждают распознавание на реальной записи,
точность разделения говорящих, оплату или доставку через настоящие сервисы.
Подтверждённой сквозной проверки Telegram → AssemblyAI → Telegram пока нет.
Запуск реальных API требует отдельного разрешения на конкретную запись и операцию.
Команды для Windows и macOS не являются заявлением о выполненных проверках на обеих ОС.

Для изменений только документации достаточно статической проверки Markdown,
внутренних ссылок, соответствия примеров коду и diff. Функциональные тесты ради
таких изменений не запускаются. Фактические результаты проверок указываются
в отчёте конкретной задачи, а не выводятся из наличия команды в документации.

Справочники: [unittest](https://docs.python.org/3.13/library/unittest.html) и
[управление синхронизацией uv](https://docs.astral.sh/uv/concepts/projects/sync/).
