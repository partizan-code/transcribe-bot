# Repository Guidelines

## Структура проекта

Проект — прототип Telegram-бота на Python 3.13 с AssemblyAI для транскрибации. Сохраняйте плоскую структуру модулей в корне:

- `main.py` создаёт бота и запускает polling через aiogram.
- `config.py` читает переменные окружения.
- `transcribe.py` — самостоятельный пример транскрибации `example.mp3` с определением языка и разделением говорящих; запрос выполняется при импорте.
- `handlers.py` пока пуст; добавляйте обработчики сообщений сюда.
- `logger_config.py` содержит `setup_logging()`, вызываемую в начале `main()`: от INFO в консоль, от ERROR в `error.log` рядом с модулем. В остальных модулях используйте `from loguru import logger`.
- `pyproject.toml`, `uv.lock` и `.python-version` описывают зависимости и версию Python.

Каталогов тестов и ресурсов пока нет; `README.md` пуст. Не вводите `src/` без отдельного согласования.

## Команды разработки

Запускайте команды из корня проекта в существующем окружении `uv`:

```sh
uv run --locked python main.py
uv run --locked python transcribe.py
```

Первая команда запускает Telegram polling; вторая отправляет локальный `example.mp3` в AssemblyAI и печатает результат. Обе требуют соответствующих ключей и обращаются к внешним сервисам. Отдельной сборки и задач mise нет. Меняйте зависимости через `uv` и сохраняйте согласованность `pyproject.toml` с `uv.lock`.

## Стиль кода

Используйте отступы в четыре пробела, `snake_case` для модулей и функций, `PascalCase` для классов и `UPPER_SNAKE_CASE` для констант. Добавляйте аннотации типов новым функциям. Сохраняйте асинхронный подход aiogram; блокирующую транскрибацию выносите из цикла событий. Используйте Loguru, не добавляя параллельную систему логирования. Ruff пока не настроен; не считайте его существующей проверкой проекта.

## Тестирование

Тестовый фреймворк и порог покрытия не заданы. Новые тесты размещайте в `tests/test_<module>.py`; имена функций начинайте с `test_`. Подменяйте Telegram и AssemblyAI заглушками, используйте временные файлы. Не импортируйте `transcribe.py` в тестах без устранения сетевого вызова при импорте. Запуск приложения с реальными ключами не заменяет изолированные тесты.

## Коммиты и pull request

Истории коммитов пока нет, поэтому устоявшийся формат отсутствует. Используйте краткие сообщения с назначением изменения, например `docs: add contributor guide`. В PR опишите результат, выполненные проверки и изменения конфигурации; приложите ссылку на задачу, если она есть. Коммит и push выполняйте только по явному разрешению.

## Конфигурация и секреты

Перед запуском задайте `BOT_TOKEN`, `ASSEMBLYAI_API_KEY` и `ALLOWED_USER_IDS` в `.env` рядом с `config.py` или в окружении. При импорте `config.py` файл загружается через `python-dotenv`; только эти три настройки читаются через `os.getenv`, уже заданное окружение имеет приоритет. ID преобразуются в множество целых чисел. Остальные настройки заданы обычными константами в `config.py` и из окружения не читаются. Класса `Settings` и дополнительной валидации конфигурации нет. Не публикуйте ключи, `.env`, `.venv`, логи, записи и транскрипты. `.gitignore` исключает локальные настройки, окружения, кэши, данные и аудио/видеофайлы; `.env.example` остаётся доступным для версионирования. Проверяйте каждый добавляемый файл.
